# Разбор входных документов и покрытие FRONTEND

> Историческая запись этапа отдельного frontend. В полной локальной версии реализованы также серверное AI-сравнение, интерфейс советника и отчёт. Актуальная сверка всех частей: [docs/REQUIREMENTS.md](../docs/REQUIREMENTS.md); актуальные инструкции — в корневом README.

Все четыре PDF прочитаны целиком: ТЗ 3 страницы, датасет 5, план 12, распределение 21. Таблицы каталога дополнительно проверены визуально. Тексты документов — проектный контекст; исполняется прямое поручение пользователя сделать только FRONTEND.

## 1. HackAlem AI — «Аким на 5 часов»

Обязательные элементы: одинаковый бюджет и исходные данные, решения по пяти доступным направлениям, контроль расходов, расчёт Score, AI-анализ сильных сторон, рисков и последствий. Цель — работающая симуляция, а не только чат. Синтетические данные допустимы.

Frontend предоставляет полный пользовательский путь, отображает вычисления и AI, сообщает об ошибках. Simulation и AI реализуют владельцы соответствующих модулей. Опциональные функции ТЗ: сравнение, визуализация, рекомендации, события, презентация. Реализованы сравнение и визуализация; UI рекомендации готов за флагом. События и презентация не входят в обязательное ядро.

Оценивание: соответствие/работоспособность 25, техническая реализация 25, README/воспроизводимость 25, ценность 15, развитие/оригинальность 10. Поэтому есть отдельные инструкции запуска, демосценарий, тесты и интеграционный документ.

## 2. Датасет районов

- Все 10 показателей направлены одинаково: 0–100, больше лучше. Критично строго ниже 40.
- Есиль 27%, Алматы 24%, Сарыарка 20%, Байконур 13%, Нура 16%.
- 14 мероприятий M1–M14 с официальными ценами, полными эффектами, типом охвата и лагом.
- Горизонт 8 кварталов; районная мера требует район, городская — нет.
- Бюджет 100; ровно 5 разных мер; максимум 2 одного направления; остаток без бонуса.
- M1/M3 несовместимы глобально; M4/M7 и M5/M13 — в одном районе.
- Синергии M1+M2, M10+M12, M5+M6; фиксированный бонус без масштабирования лагом.
- При невалидности Score отсутствует, возвращается причина. Порядок выбора не влияет.
- База 52.56; пример M7+M8+M10 в Нуре, M12, M5 в Сарыарке: 95 ед., около 56.5.

Полные числовые исходные таблицы перенесены в frontend/lib/fixtures.ts исключительно для UI; серверные shared/districts.json и shared/measures.json принадлежат интегратору. Отрицательный эффект M11 T1 −2 сохранён и видим. Официальные формулы, веса, clip и штрафы изучены, но не продублированы в JavaScript.

## 3. План проекта

Приняты продуктовые требования: рабочая панель, слабейший район, критические показатели, before/after, сравнение двух локальных сценариев, прозрачное объяснение компромиссов, возможность замены от сервера. Пять решений не означают обязательную меру в каждом направлении: применяются подробные правила датасета и его официальный пример.

План предлагает Vite/Fastify, apps/web и общие workspaces. Это расходится с подробным разделением ролей. Выбран Next.js в frontend, поскольку пользователь явно назначил роль GPT №1 из документа распределения. Собственный manifest/lockfile внутри frontend необходим для воспроизводимого самостоятельного запуска и не конфликтует с корневыми файлами участников.

Точные контрольные значения в плане: 52.55768 → 56.54307. Это статические контрольные числа; frontend не подгоняет или реализует формулу. Интерфейс различает предварительный Score и итог после finalize.

## 4. Чёткое разделение участников

Роль GPT №1: только frontend/**. Обязательные `/`, `/simulator`, `/results` выполнены; `/compare` добавлен по плану. Реализованы эквиваленты BudgetBar, DistrictPanel/Card, IndicatorBar, MeasureCard/Modal, DecisionList, Score display, RadarComparison, Timeline, SynergyAlert, AIAnalysisPanel.

Next.js + TypeScript + Tailwind + Radix/shadcn primitives + Recharts. Централизованный typed API и mocks. Backend — источник истины; прямого OpenAI вызова нет. Данные другого разработчика и общие main.py, shared/api-contract.md, README и Docker Compose не меняются. Ветка feature/frontend, не main.
