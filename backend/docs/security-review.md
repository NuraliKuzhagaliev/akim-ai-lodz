## S2. Нет контроля доступа и лимитов платного AI — высокий при публичном размещении

Публичные обработчики AI не требуют аутентификации и не ограничивают частоту/параллелизм запросов. Локальная проба выполнила 12 запросов без авторизации: все получили HTTP 200, провайдер был вызван 12 раз. Использован тестовый провайдер, расхода внешнего API не было. Заголовок Origin не ограничивает прямой HTTP-клиент: CORS не является авторизацией.

При открытом внешнем доступе посторонний клиент сможет расходовать квоту владельца и занимать обработчики. Для локального демонстрационного режима текущий Compose публикует backend на `127.0.0.1`, что уменьшает сетевую доступность.

Перед публичным размещением: аутентификация на gateway/сервере, ограничения на пользователя и общий параллелизм AI, ограничения расхода в проекте провайдера. Нельзя помещать общий серверный ключ в `NEXT_PUBLIC_*`. Без такой защиты платные маршруты не следует открывать анонимным внешним клиентам.

## S3. Нет ограничения размера HTTP-тела — средний при публичном размещении

Запрос AI с дополнительным игнорируемым полем размером 2 101 842 байта принят с HTTP 200. Поле не передано модели, но JSON уже разобран в памяти. Ограничения числа решений и длины вопроса не ограничивают весь входной HTTP-поток.

Перед публичным размещением задать лимит тела на входном прокси и/или ASGI middleware, включая потоковые запросы без Content-Length; отвечать 413 до JSON-парсинга. Для текущих структур запросов достаточно небольшого согласованного лимита (например, 64 КиБ после проверки реального максимального запроса). Политика входного прокси не была доступна для проверки.

## S4. Ограничения проверки GitHub — средний процессный риск

Для всех четырёх веток API вернул `protected=false`. У подключения есть push-доступ, административного доступа нет. Запрос rulesets вернул 403 с требованием обновить план или сделать репозиторий публичным. Видимость репозитория не менялась. Состояние Secret scanning / Push protection через это подключение не установлено — его нельзя объявлять ни включённым, ни выключенным.

Владелец должен проверить доступные защиты main, обязательное ревью и успешные проверки перед merge. Предыдущие Actions-запуски завершались до выполнения шагов без доступных логов; локальные успешные тесты не подтверждают исправность CI. Коммиты публикуются только в feature-ветки через PR, без force push.

## Дополнительное усиление

- В исходниках приложения не заданы CSP/frame-ancestors, X-Content-Type-Options и политика Referer. Настроить их на frontend/прокси с учётом Next.js. Это отсутствие защитных мер, а не доказательство XSS.
- GitHub Actions используют `actions/checkout@v4`, `actions/setup-python@v5`, Docker — `python:3.12-slim`; для воспроизводимой цепочки поставки закрепить доверенные версии по полным SHA/digest и организовать обновление. Контейнерная ОС отдельно не сканировалась.

## Что уже защищено

- `.env` исключён Git и Docker-контекстом; `.env.example` в актуальных ветках содержит пустое поле ключа.
- Сервер пересчитывает данные по ID решений. При подмене Score на 999999 и spent на 0 AI получил реальные 56.54307 и 95.
- Ответы провайдера валидируются схемой; ошибки возвращают безопасный 503 без текста исключения и ключа.
- Интегрированный `/api/ai/advice` проверяет каждую рекомендацию детерминированным валидатором и сам не меняет план.
- Разрешённые CORS origins перечислены явно; Docker работает от непривилегированного пользователя.
- Не обнаружены вызовы eval/exec, небезопасная десериализация pickle, пользовательские URL для серверного fetch или `dangerouslySetInnerHTML` в проверенном коде. Это результат анализа текущих файлов, не доказательство отсутствия любого варианта эксплуатации.
