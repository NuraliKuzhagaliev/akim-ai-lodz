# Интеграция AI и backend

Источник AI-кода: `feature/ai`, коммит `45c916985be227cd4116bdfac96e764466732888`. Модули `app/ai/**` и `app/report/**` перенесены без изменения в `feature/simulation`. История AI-ветки не объединялась: в ней найден старый коммит с секретом. Актуальные файлы и `.env.example` секрета не содержат. Подробности — `security-review.md`.

Точка входа: `backend/app/main.py`, `app.main:app`. Зависимости провайдера закреплены в настоящем `backend/requirements-ai.txt`, включающем `requirements.txt`. Установка из `backend/`: `python -m pip install -r requirements-ai.txt`. Значения окружения задаёт оператор; ключ остаётся только на сервере.

Dockerfile также устанавливает `requirements-ai.txt`. Compose передаёт `OPENAI_API_KEY` и `OPENAI_MODEL` из окружения запуска; без ключа расчёты доступны, AI возвращает 503. Для локального файла `backend/.env` команда из корня: `docker compose --env-file backend/.env up --build`. Файл должен существовать и содержать отозванному ключу замену; не добавлять его в Git. `docker compose config` может раскрыть подставленный ключ — не публиковать его вывод. Образ не включает `.env`. Сборка контейнера в текущем окружении не выполнялась: Docker недоступен.

Публичные пути:

- `/api/ai/analyze` и `/api/explain`: полный план, сервер пересчитывает все числа, AI объясняет результат.
- `/api/report/executive-brief`: сервер строит расчёт и анализ для отчёта.
- `/api/ai/advice`: 0–4 решения, AI предлагает отдельные добавления, backend проверяет каждое своим валидатором.
- `/api/recommend`: детерминированный поиск одной замены в полном плане, без вызова AI.

Сырые `create_ai_router()` и `create_report_router()` не монтируются поверх адаптеров: они принимают готовые факты и создали бы дублирующие пути с возможным обходом пересчёта. Используются их сервисы и фабрики провайдера. Это сохраняет код участника AI и единственный источник расчётов.

Общий HTTP-контракт — `shared/api-contract.md`, машинная схема — `shared/openapi.json`. Совет принимает решения, а не внутреннюю схему `AdviceRequest`. Ответ совета сохраняет snake_case AI-модуля; поля `validation_mode` и `base_scenario_id` описывают, к какому состоянию относится проверка. Предложения являются альтернативами. Повторная проверка всего набора перед применением обязательна.

В локальной сборке добавлен `/api/ai/compare`: два массива решений финализируются сервером, AI получает два snapshot и рассчитанные разницы. Поля ID, версии и checksum проверяются frontend. Советник и Markdown-отчёт также подключены к интерфейсу. Актуальный запуск — в корневом README; здесь сохранено описание происхождения AI-модулей.

Проверки: `python -m pytest`, `python scripts/check_ai_contract.py`; проверка реальных схем frontend — `node backend/scripts/check_frontend_contract.mjs` из корня после объединения с frontend. В CI/без ключа используются контролируемые провайдеры. Они проверяют границы интеграции, но не подтверждают доступность внешней модели.
